# 🙂 emoji-sticker-info-bot

Telegram-бот для получения и обратного поиска ID обычных и Premium emoji, стикеров и целых паков. Бот умеет обрабатывать отдельные элементы, ссылки на паки и готовые идентификаторы. Результат можно экспортировать в TXT, а администраторы могут настроить единый формат ответа через `/admin`.

> Бот в Telegram: [@emoji_info_bot](https://t.me/emoji_info_bot)

Бот работает в личных чатах через long polling. Для самостоятельного запуска нужны Python 3.11+, токен от BotFather и Telegram ID первого администратора; webhook, домен и Redis не нужны.

## 🚀 Возможности

- Получение `custom_emoji_id` для Premium/custom emoji;
- Получение Unicode-кода для обычных emoji, например `U+1F34F`;
- Получение `file_id` и `file_unique_id` обычных и Premium-стикеров;
- Обработка ссылок `t.me/addemoji/...` и `t.me/addstickers/...`;
- Вывод всех доступных ID из больших emoji- и sticker-паков;
- Обратный поиск Premium emoji по `custom_emoji_id`;
- Отображение обычного emoji по Unicode-коду;
- Отправка стикера по его `file_id`;
- Удаление повторов и автоматическое разделение длинных результатов;
- Нативная кнопка копирования одиночного ID;
- Экспорт полного результата в TXT;
- Русский и английский интерфейс;
- Premium emoji в сообщениях и inline-кнопках с автоматическим fallback-режимом.

## 🔄 Что можно отправить

| Входные данные | Что вернёт бот |
|---|---|
| Обычный emoji | Unicode-код |
| Premium/custom emoji | `custom_emoji_id` |
| Стикер | `file_id` по умолчанию; другие ID и детали включаются администратором |
| Ссылка на emoji-пак | ID всех элементов пака |
| Ссылка на sticker-пак | ID всех стикеров пака |
| `custom_emoji_id` | Соответствующий Premium emoji |
| Unicode вида `U+1F34F` | Соответствующий обычный emoji |
| `file_id` стикера | Сам стикер |

> `file_unique_id` подходит для сравнения файлов, но по нему нельзя повторно отправить или скачать стикер.

## ⚙️ Админ-панель и настройки

Команда `/admin` открывает панель с Premium-эмодзи и цитатами. Для обычных пользователей эта команда остаётся без ответа; кнопок настроек у них нет. Администраторы видят кнопку **Настройки** в главном меню и под результатами. Сама админ-панель открывается только командой `/admin`, без кнопки входа. Язык интерфейса определяется по языку Telegram: русский или английский, для остальных языков — русский.

В панели доступны четыре раздела:

- **Настройки** — Общий формат новых ответов;
- **Администраторы** — Добавление и отзыв доступа;
- **Предпросмотр** — Демонстрационный результат с текущим оформлением эмодзи, стикеров и повторов, без изменения настроек;
- **Состояние бота** — Время работы процесса, режим Long polling, доступность базы настроек для чтения, число администраторов и актуальных TXT-экспортов в кэше.

По умолчанию каждая строка имеет вид `emoji - ID`, без нумерации, скобок и заголовков:

```text
✈️ - 6028346797368283073
🏐 - U+1F3D0
```

Администраторы могут изменить общий формат для всех новых ответов:

- Premium emoji, обычный fallback или оба варианта одновременно;
- ID в квадратных скобках, моноширинным кодом или без оформления;
- Нумерацию, маркированный список или строки без префикса;
- Пробел, тире или перенос строки между элементом и ID;
- Пробел после маркера, вокруг тире и между двумя вариантами emoji;
- Вывод `file_id`, `file_unique_id` или обоих значений;
- Технические данные стикеров;
- Заголовок и ссылку на исходный пак;
- Удаление повторов;
- Premium-иконки inline-кнопок обычного меню.

Изменения не переформатируют уже отправленные сообщения и готовые TXT-файлы. Кнопка сброса возвращает общий формат по умолчанию, не затрагивая список администраторов.

При обратном поиске по `custom_emoji_id` бот показывает сам Premium emoji, даже если для обычных списков выбран стандартный вариант отображения.

### 👥 Управление администраторами

1. Укажите ID первого администратора в `ADMIN_IDS` файла `.env` перед запуском.
2. Откройте `/admin` → **Администраторы** → **Добавить администратора**.
3. Отправьте числовой Telegram ID нужного человека и подтвердите выдачу прав. Для отмены нажмите **Назад** или отправьте `/cancel`.
4. Для отзыва прав нажмите **Удалить** рядом с ID и подтвердите действие.

Каждый администратор может менять настройки и управлять дополнительными администраторами. Администраторы из `.env` защищены от удаления через панель: их список меняется только в `ADMIN_IDS` с перезапуском бота. Можно добавить до 50 дополнительных администраторов; их доступ сохраняется после перезапуска.

## ⚡ Быстрый запуск

### 1. 📥 Клонирование

```bash
git clone https://github.com/shirstylee/emoji-sticker-info-bot.git emoji-sticker-info-bot
cd emoji-sticker-info-bot
```

Предварительно установите Git и Python 3.11 или новее. Выполняйте дальнейшие команды из корня проекта.

### 2. 🐍 Установка на Windows

Все зависимости устанавливаются только в локальное окружение `.venv` внутри проекта:

```powershell
.\setup.ps1
```

Скрипт создаст `.venv`, установит проект с dev-зависимостями и подготовит `.env`, если его ещё нет.

### 3. 🔑 Настройка окружения

Получите токен у [@BotFather](https://t.me/BotFather) и заполните `.env`:

```dotenv
BOT_TOKEN=your_bot_token
ADMIN_IDS=123456789
DB_PATH=data/bot.db
LOG_LEVEL=INFO
```

Файл `.env` содержит секретный токен, исключён из Git и не должен публиковаться.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Обязательный токен вашего бота от BotFather |
| `ADMIN_IDS` | Обязательные числовые Telegram ID администраторов через запятую, например `123456789,987654321` |
| `DB_PATH` | Путь к SQLite-базе общих настроек и дополнительных администраторов; по умолчанию `data/bot.db`, относительно папки запуска |
| `LOG_LEVEL` | Уровень логирования; обычно `INFO` |

Для самостоятельной копии создайте отдельного бота. Запускайте один polling-процесс на один токен.

Замените пример `ADMIN_IDS` на свой Telegram ID, не на ID бота, никнейм или номер телефона. При пустом или некорректном `ADMIN_IDS` бот остановится с понятным сообщением до подключения к Telegram.

### 4. ▶️ Запуск

```powershell
.\run.ps1
```

Или напрямую через Python из локального окружения:

```powershell
.\.venv\Scripts\python.exe -m emoji_id_bot.main
```

### Linux и macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
cp .env.example .env
# Заполните BOT_TOKEN и ADMIN_IDS в .env перед запуском.
python -m emoji_id_bot.main
```

## 🤖 Команды

- `/start` — Главное меню;
- `/help` — Инструкция и примеры входных данных;
- `/admin` — Панель администратора, только для ID с выданными правами;
- `/cancel` — Отмена ввода нового администратора и возврат в меню.

Команда `/settings` доступна только администраторам и открывает настройки результата, а не админ-панель. Для остальных пользователей она остаётся без ответа. В обычном списке команд отображаются только `/start` и `/help`.

### 🔄 Обновление с предыдущей версии

Остановите старый процесс, обновите проект, добавьте `ADMIN_IDS` в серверный `.env` и запустите бота. При первом запуске старая таблица индивидуальных настроек автоматически удаляется, вместо неё создаётся общая конфигурация с новым форматом по умолчанию. Предыдущие индивидуальные настройки не переносятся. После запуска настройте общий результат через `/admin`.

## 🔒 Безопасность

- Доступ к админ-командам и callback-кнопкам проверяется по Telegram ID при каждом обращении;
- Добавление и удаление администратора требуют подтверждения, а ID из `.env` защищены от удаления через панель;
- Бот отвечает только в личных чатах, поэтому чужие пользователи не могут нажимать кнопки вашего меню;
- Сообщения и inline-кнопки защищены локальным антифлудом;
- Один пользователь не может запустить несколько обработок текстовых запросов одновременно;
- Одновременно выполняется не более 8 обработок, а ссылки на паки имеют паузу 8 секунд;
- Диспетчер не создаёт больше 50 параллельных задач для входящих обновлений;
- Сообщения, отправленные другими ботами, игнорируются;
- Никогда не публикуйте `.env` и токен BotFather;
- Перед каждым коммитом проверяйте файлы командой `git status`;
- Если токен попал в Git, сразу отзовите его через BotFather и создайте новый;
- Не добавляйте локальную базу `data/bot.db` в репозиторий;
- Подробная инструкция первой публикации находится в [`GITHUB_SETUP.md`](GITHUB_SETUP.md).

По умолчанию допускается 8 сообщений и 15 нажатий кнопок за 5 секунд от пользователя. Ограничения хранятся в памяти одного процесса и сбрасываются при перезапуске.

В одном запросе обрабатывается до 5 ссылок на паки и показывается до 20 стикеров по `file_id`. TXT-экспорт хранится до часа; кэш вмещает до 500 результатов на весь процесс, поэтому при высокой нагрузке старые экспорты могут исчезнуть раньше.

Подробности и приватное сообщение об уязвимости — в [SECURITY.md](SECURITY.md).
